# GizeMate 1.6.0: security and privacy review

Scope: the diff from v1.5.0 (`3d247af`) to the release commit, the shipped Windows payload and the Android release artifacts. Labels: REAL (executed here), REVIEWED (read, not executed).

| Area | Result | Evidence |
|---|---|---|
| Dependencies, shipped | 0 known vulnerabilities (REAL) | `npm audit --omit=dev`: 0 of every severity |
| Dependencies, tooling | 14 moderate advisories, all in build/lint tooling (electron-builder, app-builder-lib, eslint, typescript-eslint, minimatch and relatives); none ships in the app (REAL) | `npm audit`; not fixed because the fixes are major upgrades of the build tool chain, out of scope for a release candidate |
| Network | The only external host in shipped source is `api.anthropic.com`, inside the consent-gated cloud allowlist (off by default); everything else is localhost/documentation links. No telemetry (REVIEWED) | grep of `src/` for URLs; docs/PRIVACY.md invariants unchanged |
| Secrets in the repository | No keystore, key, payload or credential file tracked; no key-like string literals (REAL) | `git ls-files` filter and `git grep` scan. `android/keystore.properties.example` is a template |
| Secrets in the builds | Only ciphertext of the optional hidden-feature payload is embedded: 2 occurrences per Windows `app.asar` and 0 private-path strings in both architectures (REAL); the Android web bundle was rebuilt with the same ciphertext-only embedding. No signing material is in any artifact (REAL) | `.claude/state/gizemate/check-pkg.cjs`, build logs |
| Local data | New files `characters/<id>.json` hold the same kind of content as the cat's state (no screen content, no keystrokes). Written atomically by the existing store (REVIEWED) | docs/characters, `src/main/store` |
| Memory persistence, import/export | Profile format unchanged (1.1), still cat only, never carries device-only GizeMate fields; v1.5.0 profiles import unchanged (REAL, unit test `gizemateCompat`) | tests/unit/main/gizemateCompat.test.ts |
| Permissions | No new Windows capability. Android: the release APK still declares exactly FOREGROUND_SERVICE, FOREGROUND_SERVICE_SPECIAL_USE, POST_NOTIFICATIONS and SYSTEM_ALERT_WINDOW, not debuggable (REAL, `aapt2 dump badging`) | `scripts/verify-android-artifacts.mjs` |
| Installer behaviour | Per user, no elevation; `deleteAppDataOnUninstall` false; installer script and NSIS GUID identical to v1.5.0; the only registry deletes are the app's own startup values (REAL, static) | `scripts/inspect-installer.mjs`, record in 1.6.0-validation-record.md |
| Renderer isolation | Sandbox, context isolation, validated IPC unchanged; test hooks and DevTools absent from packaged builds (REVIEWED; packaged smoke ran with no hooks) | CLAUDE.md invariants, smoke results |
| Signing | Windows installers: **unsigned**, `NotSigned` (REAL), no certificate exists; this is stated in the release notes. Android APK and AAB: signed with the project's existing release key (APK scheme v2, AAB jarsigner, same certificate, the same one as the 1.5.0 build) (REAL). The key and passwords were read from the owner's existing local configuration into the build process only; they were never printed, copied or committed, and no credential file is tracked (REAL, `git ls-files`) | `Get-AuthenticodeSignature`, `apksigner`, `jarsigner` |
| Build hook | `build/afterSign.cjs` rewrites only the exe's two display strings (FileDescription, ProductName) with the same library electron-builder uses; no identifier, path or executable name changes; the inspector fails if they are wrong (REAL) | `scripts/inspect-installer.mjs` |

Not covered: an external penetration test; fuzzing; Windows on Arm runtime; Android runtime behaviour on a device; the previously exposed cPanel token (the owner must revoke it; it was neither used nor stored).
