## Windows

- **Static inspection (STATIC, `scripts/inspect-installer.mjs`, nothing executed).** Both installers: SHA-256 and size match the files; NSIS GUID equal to v1.5.0 (`e1021757-1dcb-56be-999c-26e3a22d4339`); `deleteAppDataOnUninstall` false; per-user, no elevation; payload has no forbidden files; `check-win-payload --strict` ok. Exe version resource ProductName and FileDescription are **GizeMate** (set by `build/afterSign.cjs`; the first build exposed that `afterPack` was too early and the inspector now fails on a wrong name). Configuration changes against v1.5.0, all intended: `shortcutName`, `uninstallDisplayName`, `artifactName` and `installer.nsh` message text. Frozen and unchanged: `appId`, `productName`, executable `DesktopCat.exe`, install folder, data folder `%APPDATA%\Desktop Cat`, GUID.
- **Packaged x64 app, launched in isolation (REAL).** `scripts/smoke-packaged.mjs`: no error lines, second instance exits, no login-item writes; `scripts/smoke-packaged-characters.mjs`: all seven characters start (alive, no error lines). Pixels were not examined. **ARM64: never run (no hardware).** **The installers were never executed**: install, update over 1.5.0 and uninstall are reasoned from configuration, not observed (see the install guide for the safety copy).
- **Signing:** no Windows code-signing certificate exists in any store or environment on this PC, so nothing was signed and none of the installers is represented as signed.

**Verification reliability fix.** The two long simulation tests that timed out under machine load (`bands-short`, `bands-scenarios`) and ten other timeout-prone files now use explicit wall-clock timeouts that scale (`tests/helpers/slowTimeout.ts`: by `VITEST_TEST_TIMEOUT_MS / 60000`, at least 3x). They are hang guards for deterministic CPU-bound simulations; one asserted at most 120 s of CPU time under a 60 s wall-clock limit. **No assertion was changed or weakened**; the CPU-time budget assertion is intact. Three consecutive full runs after the change had no timeout.
