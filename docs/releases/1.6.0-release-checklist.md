# GizeMate 1.6.0: owner release checklist

Everything technical that could be done without owner authority is done (see [1.6.0-validation-record.md](1.6.0-validation-record.md)). These steps remain, in order. Items marked **owner** need your key, account, hardware or decision.

## 1. Before releasing
- [ ] **owner** Re-run `node .claude/scripts/verify.mjs fast` on an idle PC if you want your own pass.
- [ ] **owner** On a test PC or VM (or after backing up `%APPDATA%\Desktop Cat`): install the x64 installer over a 1.5.0 install; confirm cat and settings survive; uninstall; confirm data stays.
- [ ] **owner** Run the 15-minute live checklist in [1.6.0-live-validation.md](1.6.0-live-validation.md).
- [ ] **owner** Listen to `release/audio-review-1.6.0/*/*.wav` and check the sounds; try a screen reader and touch if you can.
- [ ] **owner** Decide the final product name (GizeMate is provisional; the display layer is `src/shared/brand.ts`, frozen identifiers are not to change).

## 2. Windows
- [ ] **owner** Sign both installers (see docs/platforms/windows-signing.md), then recompute and record the SHA-256 (signing changes the file).
- [ ] Unsigned alternative: publish as unsigned and state it (SmartScreen warns).

## 3. Android 1.6.0 (not built here)
The source is ready (`versionName 1.6.0`, `versionCode 10600`). A signing configuration exists on this PC in your own GizeCat clone (`android/keystore.properties`); it was deliberately not read, copied or used, because signing with your credentials is your action.
- [ ] **owner** In a checkout of this branch, make the signing source available as described in docs/platforms/android-signing.md (four environment variables, or `android/keystore.properties`), keeping the same production key as 1.4.2.
- [ ] **owner** `npm ci --ignore-scripts` then `npm run android:release` (JDK 17+, Android SDK platform 36). Check the output name does not end in `-unsigned`.
- [ ] **owner** Test the APK on a real device; no Android test or emulator was run by me.

## 4. Git and tag (proposed; nothing done)
- Strategy: open a PR `feature/gizemate` into `main` and merge with a merge commit (keeps the 14 commits and their trailers; do not squash). Re-run `verify fast` on the merge result.
- Tag: annotated `v1.6.0` on the merge commit, after signing, so the tag matches the published files.
- Release assets: both installers (and the Android APK if built) with SHA-256 values from the inventory (or the signed values).
- Then update `CHANGELOG.md` (remove "release candidate") and the website download links.
