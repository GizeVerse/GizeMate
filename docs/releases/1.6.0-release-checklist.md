# GizeMate 1.6.0: release checklist

Status after the technical release. Everything the builders could do and verify is done and recorded in [1.6.0-validation-record.md](1.6.0-validation-record.md). What remains needs your hardware, accounts or decisions.

## Done (technical)
- [x] Version 1.6.0 everywhere (`package.json`, `android/version.properties` 1.6.0 / 10600); frozen identifiers unchanged.
- [x] GizeMate branding across Windows (shortcuts, Apps entry, installer and exe names), Android (label, file names), web, README and docs.
- [x] `verify fast` passes on the release commit; desktop, accessibility and web suites pass (counts in the validation record).
- [x] Windows x64 and ARM64 installers built from a clean tree, statically inspected, packaged x64 app launched with all seven characters.
- [x] Android APK and AAB built from a clean tree, signed with the existing release key, verified (signature, package, version, same certificate as 1.5.0).
- [x] Release notes, install and upgrade guide, known limitations, security review, inventory, test report.
- [x] Merge into `main` (merge commit), tag `v1.6.0`, GitHub release with the four artifacts and `SHA256SUMS.txt`.

## Open (owner)
- [ ] **Try the Windows update once** on a test PC or after backing up `%APPDATA%\Desktop Cat`: install over 1.5.0, confirm your companion survives and the old shortcuts are replaced; uninstall and confirm the data folder stays. The installers have never been executed by the builders.
- [ ] **Test the Android APK on your devices** (install over 1.5.0, float, drag, rotate, switch characters, Turkish). No device or emulator test was run.
- [ ] **Sign the Windows installers** when you have a certificate (docs/platforms/windows-signing.md), then publish the signed files with new hashes in place of the unsigned ones. Until then the release notes say they are unsigned.
