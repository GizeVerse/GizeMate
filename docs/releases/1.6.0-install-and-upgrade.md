# GizeMate 1.6.0: install and upgrade

Check every download against `SHA256SUMS.txt` on the [release page](https://github.com/GizeVerse/GizeMate/releases/tag/v1.6.0) (`Get-FileHash <file> -Algorithm SHA256` in PowerShell) before running it.

## Windows 10 / 11

Files: `GizeMate-Setup-1.6.0-x64.exe` (Intel/AMD) or `GizeMate-Setup-1.6.0-arm64.exe` (Windows on Arm).

**The installers are not code-signed** (no signing certificate was available). SmartScreen shows "Windows protected your PC"; choose *More info → Run anyway*, only after the hash matches. Smart App Control, if on, may block unsigned installers.

### Clean install
Run the installer. It installs for the current user (no administrator rights), lets you pick a folder (default `%LOCALAPPDATA%\Programs\DesktopCat`), creates "GizeMate" Desktop and Start menu shortcuts and starts the app. On first start a Welcome page explains the controls; pick a companion under **Characters**.

### Update from 1.5.0 or earlier
1. Optional safety copy: close GizeMate (tray icon → Quit), then copy `%APPDATA%\Desktop Cat` somewhere.
2. Run the new installer over the old install. It keeps the same application identity, install folder and data folder, so your companion, settings, memory and journal are kept. The old "Desktop Cat" shortcuts are replaced by "GizeMate" shortcuts.
3. Start GizeMate. Your cat is back, and the other six companions are available under Characters.

Why the old names remain inside: the program file is `DesktopCat.exe` and the data folder is `Desktop Cat`. They are internal identifiers; renaming them would orphan existing data, so they are deliberately kept ([docs/gizeverse/12-branding.md](../gizeverse/12-branding.md)).

> **Status of this procedure:** reasoned from the installer configuration and electron-builder's behaviour, checked statically (same application id, same NSIS GUID, same install location logic, uninstall never deletes the data folder). **The installer has not been executed** by the builders, so a real update has not been observed. If anything looks wrong, the safety copy above restores your data.

### Uninstall
Windows Settings → Apps → GizeMate → Uninstall. This removes the startup entry; your data folder is kept. Delete `%APPDATA%\Desktop Cat` yourself to remove everything.

## Android 10 or later

Files: `GizeMate-1.6.0-android.apk` (install directly) and `GizeMate-1.6.0-android.aab` (Google Play bundle; not installable by hand).

1. Download the APK and check its hash. Open it and allow "Install unknown apps" for the app you opened it from.
2. Open GizeMate, tap **Float over apps**, read the explanation, and grant **Display over other apps** in Android's own settings page yourself. It never starts by itself, not even after a reboot.
3. **Updating from 1.5.0 (release-signed):** the APK has the same package and the same signing certificate (checked by `scripts/verify-android-artifacts.mjs`), with a higher versionCode, so Android installs it over the old one and keeps your companion.
4. **From a "GizeCat (trial)" build:** that is a different app (it uses a separate package and the debug key). Open it, use *Take your companion to another device* to save your cat to a file, install GizeMate, load the file there, then uninstall the trial app.

Google Play Protect may ask you to confirm an app from outside the store. The APK has not been run by the builders; please report problems at <https://github.com/GizeVerse/GizeMate/issues> with your device model and Android version.
